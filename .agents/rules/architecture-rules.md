- Inspect the existing codebase before coding.
- Reuse existing components before creating new ones.
- Never duplicate existing functionality.
- Follow Single Responsibility Principle.
- Keep page components thin.
- Separate UI, business logic, API logic, utilities, constants, and types.
- Prefer feature-based folder structure.
- Do not create monolithic 500+ line files.
- When a file becomes large, split it by responsibility.
- Extract reusable components and hooks.
- Search the repository before creating a new component.
- Do not create duplicate API clients/services.
- Do not create duplicate CSS/design-system components.
- Preserve existing architecture unless there is a concrete reason to change it.
